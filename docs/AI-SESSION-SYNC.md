# AI 会话备份与恢复

> 本文只描述当前功能。被替换的历史方案不保留在工作区文档中，需要追溯时查看 Git 历史。

## 当前能做什么

- 自动发现本机 Claude / Codex 会话，可搜索、排序和预览真实对话。
- 用一个自己管理的私有 Git 仓库，在两台电脑之间备份和恢复会话。
- 内容相同或只在末尾继续增长时自动对齐；真正分叉时才询问保留哪份。
- 默认把删除的会话移进本机系统废纸篓；只有显式选择后才同步删除记录。
- 详情提供可复制的继续命令；Moo Fleet 不直接启动 Claude 或 Codex。

## 第一次设置

在“AI 会话”页点击“同步会话”，选择备份位置：

| 选择 | 结果 |
| --- | --- |
| 只备份在本机 | 使用 Moo Fleet 数据目录，不跨电脑 |
| 候选文件夹 | 选择扫描到的新版备份仓、旧版备份仓或空 Git 仓库 |
| 其他文件夹 | 通过系统目录选择器指定本机文件夹 |

要跨电脑使用：

1. 在 Gitee 或 GitHub 新建一个空的私有仓库，不要初始化 README、License 等文件。
2. A 机 clone 该仓库，在 Moo Fleet 中选中这个文件夹并同步。
3. B 机 clone 同一仓库，在 Moo Fleet 中选中它并同步。
4. 之后每次换电脑前后各点一次“同步会话”。

Moo Fleet 不保存用户填写的远端地址，只读取所选仓库自身的 `origin`。没有 `origin` 时仍可本机备份；带内嵌用户名、密码或 Token 的远端会被拒绝。fetch / push 跟随仓库当前分支。

### 旧版备份仓

能识别的旧版 Vault 会显示“旧版备份仓”。首次使用必须再次确认，确认后工作树升级为当前格式，旧内容仍留在 Git 历史中。普通有内容的仓库始终拒绝，不能通过确认标志绕过。

## 同步规则

本机 Claude / Codex JSONL 是真相，备份仓是派生副本。同步时按 provider 和会话 ID 配对：

- 只有一边存在：写入备份或恢复到本机。
- 一边完整包含另一边：自动使用更完整的一边。
- 两边从同一点继续写出不同内容：选择“用这台”“用另一台”或“两份都留”。
- 备份记录显示另一台已经删除、本机仍存在：选择保留本机或跟随删除。

恢复 Claude 会话时优先用 Git 远端推导的 `projectId` 找到本机项目；找不到时按备份相对路径落地。Codex 会话保留原始内容，其中记录的旧电脑 `cwd` 不会被改写。

私有 Git 暂时连不上时，本机备份仍会完成并显示原因；未推送提交会在下次联网同步时继续上传。同步不是实时的，只在用户点击时发生。

## 删除与继续

- 普通删除只影响当前电脑，并进入系统废纸篓。
- 选择“同时移出备份”后才写删除记录；另一台已有文件不会被静默删除，而是在同步时要求确认。
- “两份都留”会创建带来源标记的副本，列表中显示“副本”。

继续命令示例：

```sh
cd '<项目目录>' && claude --resume '<sessionId>'
cd '<项目目录>' && codex resume '<sessionId>'
```

界面可选加入 provider 的跳过权限确认参数；默认关闭，选择只保存在本机。项目目录和会话 ID 都经过 shell 引用，命令只用于复制，Moo Fleet 不执行它。

## 安全边界

- 只同步完整的会话 JSONL，不同步项目源码、未提交改动、登录态、API Key、Cookie、缓存、SQLite、锁文件或机器配置。
- 备份位置只能是空目录、无提交的空 Git 仓、新版备份仓，或经明确确认的可识别旧版 Vault。
- 正在写入但尚未换行的最后一行不会进入备份，也不参与版本判断。
- 同步、冲突处理和删除串行执行，避免多个操作同时修改同一个 Git 工作树。
- 会话内容在私有仓库中是明文，任何拥有仓库权限的人都能读取，Git 历史也会长期保留。
