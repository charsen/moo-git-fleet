# AI 会话备份与恢复

> 本文描述当前业务与实现。被替换的历史方案只保留在 Git 历史和 `GIT-FLEET-PLAN.md` 的历史档案中，不作为运行依据。

## 1. 当前能力

- 扫描本机全部 Claude / Codex 会话，可按关键词、provider、备份状态和时间排序筛选。
- 会话详情展示最近 200 条可读消息；工具回执、环境上下文等系统噪声会被过滤，备份仍保留完整 JSONL。
- “等待备份”筛出尚未备份、内容已变化或备份中已被另一台删除的会话；切换仓库与会话工作区不会丢失当前搜索和筛选。
- 使用一个自己管理的本机 Git 仓库备份会话；仓库配置 `origin` 后可在两台电脑间同步。
- 内容相同或只有严格前缀延伸时自动选择更完整的一方；真正分叉或遇到跨机删除时才要求用户决定。
- 普通删除进入当前电脑的系统废纸篓；列表可逐条勾选或全选当前筛选结果，搜索、provider 或备份状态变化时会清空选择，避免误删隐藏项。
- 只有显式勾选后才在备份中写入删除墓碑；批量删除在单一备份锁内逐条处理，单项失败不阻断其他项，成功项统一为一次 Git 提交和一次 Push。
- 详情可生成并复制继续命令；Moo Fleet 不直接启动 Claude 或 Codex。

## 2. 真相源与备份结构

本机 provider JSONL 是真相源，备份 Git 仓是 Fleet 管理的派生副本。备份仓顶层只允许：

```text
.git/
fleet.json
sessions/
  claude/
    <sessionId>.jsonl
    <sessionId>.json
  codex/
    <sessionId>.jsonl
    <sessionId>.json
```

- `.jsonl` 保存 provider 原始会话内容。
- 同名 `.json` 保存标题、项目身份、来源设备、内容摘要、更新时间和删除状态。
- 删除墓碑只保留 `.json`，会话原文 `.jsonl` 从当前工作树移除；Git 历史仍可能保留旧内容。
- 会话 ID 会直接进入文件名，写入前必须满足安全文件名规则，不能含路径穿越片段。
- 会话可能很大，同一会话每次变化都会在 Git 历史形成新版本；单条达到 20MB 时同步结果会提醒仓库增长风险。

## 3. 第一次设置

在“AI 会话”页点击“同步会话”，选择备份位置：

| 选择 | 结果 |
| --- | --- |
| 只备份在本机 | 使用 Fleet 数据目录下的建议位置，不跨电脑 |
| 会话备份仓 | 使用扫描到的新版 Fleet 备份仓 |
| 空 Git 仓库 | 使用还没有任何提交的 Git 仓库 |
| 旧版备份仓 | 再次确认后清理旧版工作树并升级为当前结构 |
| 其他文件夹 | 通过 macOS 原生目录选择器或路径输入指定位置 |

要跨电脑同步：

1. 在 Gitee、GitHub 或其他 Git 服务创建一个空的私有仓库，不初始化 README、License 或其他文件。
2. A 机 clone 该仓库，在 Moo Fleet 中选择这个文件夹并同步。
3. B 机 clone 同一仓库，在 Moo Fleet 中选择它并同步。
4. 每次换电脑前后各点一次“同步会话”。同步不是实时后台服务。

Fleet 不接收和保存用户填写的远端地址，只读取所选仓库自己的 `origin`。没有 `origin` 时仍可本机备份；HTTP(S) 远端若包含用户名、密码、查询参数或 fragment 会被拒绝。同步跟随所选仓库当前分支；Fleet 自己初始化且无法识别分支时才使用 `main`。

### 备份位置守卫

允许的目标只有：

- 空目录。
- 没有提交的空 Git 仓库。
- 带 `fleet.json` 所有权标记的当前 Fleet 会话备份仓。
- 同时具有旧版标记和旧版目录结构、且用户再次确认的旧版 Vault。

普通有内容仓库始终拒绝，即使请求带有旧版升级确认也不能绕过。Fleet 源码仓及其内部路径也不能作为备份位置。原因是同步会在这个受管派生仓中执行 `reset --hard`、`clean -fd` 和顶层旧内容清理；这些操作绝不能落到用户代码仓。

更换位置时，当前目录会单独补回候选列表、标记“当前使用中”并默认选中。位置没有变化时不能重复保存。从带远端的备份仓切换到无远端目录，界面会明确提示跨电脑同步将停止；原位置和远端内容不会被删除。

## 4. 一次同步如何执行

备份仓的写操作统一进入单一串行队列。一次“同步会话”依次执行：

1. 如果配置了远端，Fetch 当前备份分支。
2. 保存尚未推送的本机删除墓碑，再把受管备份工作树对齐到远端 tip；远端为空时视为正常首次同步。
3. 恢复 Fleet 所有权标记，移除被远端重新带回的旧版顶层结构。
4. 扫描全部本机 Claude / Codex 会话，并与备份中的 provider + session ID 配对。
5. 文件大小与 mtime 已证明未变化时直接跳过；其余内容只比较完整 JSONL 行。
6. 自动备份本机新增/延伸内容，或把备份新增/延伸内容恢复到本机。
7. 把真正分叉和“备份已删除但本机仍存在”的条目交给用户决定。
8. 统一提交备份工作树；有远端且本轮在线时 Push 当前分支。

远端 Fetch 或 Push 失败不会撤销已经完成的本机备份。页面会显示失败原因，未推送提交在下一次联网同步时一并上传。远端不可用时不会为了“保持 Git 干净”丢弃本机内容。

## 5. 内容关系与用户决策

Claude / Codex 会话采用追加写 JSONL。既有完整行不会被改写，因此无需事件流、checkpoint 或通用 diff，只需逐行判断严格前缀：

| 关系 | 自动行为 |
| --- | --- |
| 两边相同 | 跳过 |
| 只有本机存在 | 写入备份 |
| 只有备份存在 | 恢复到本机 |
| 备份是本机的严格前缀 | 用本机更新备份 |
| 本机是备份的严格前缀 | 把备份追加内容恢复到本机 |
| 共同前缀之后两边内容不同 | 等待用户决定 |
| 备份是删除墓碑、本机仍存在 | 等待用户决定 |

分叉时可选择：

- “用这台”：用本机内容更新备份。
- “用另一台”：用备份内容覆盖本机文件。
- “两份都留”：保留当前会话，并把备份内容以 `<原 ID>--<设备名>` 副本写入本机。

跨机删除时可选择：

- “保留本机”：把本机内容重新写回备份，覆盖墓碑。
- “本机也删除”：把本机会话移到系统废纸篓，保留删除墓碑。

界面会显示共同前缀行数和两边分叉后的第一句可读内容，帮助用户判断。每次处理一条待决策项都会在串行锁内重新读取本机会话和当前备份文件，不直接拿旧的 UI 内容执行写入。

### 批量删除

- 客户端把明确勾选的 provider + session ID 清单提交给服务端，最多 500 条；不把搜索条件当作隐式删除范围。
- 默认只处理本机文件并移入系统废纸篓。选择“同时从备份中移除”时，服务端会在移动任何本机文件之前确认备份绑定和仓库仍然可用。
- 服务端重新扫描当前会话，逐条返回本机删除、墓碑写入和错误状态；找不到或废纸篓操作失败的条目不会阻断同批其他会话。
- 只为已经成功移入废纸篓的条目写墓碑，整批墓碑只提交和上传一次。Push 失败不会撤销本机删除或本机墓碑，页面会说明下次同步将继续上传。

## 6. 完整行与正在写入的会话

只有以换行结束的 JSONL 行才算完整。provider 正在写最后一行时：

- 未换行的尾部不会进入备份。
- 未换行的尾部不参与相同、前缀或分叉判断。
- 下一次同步时，写完整的新行会正常进入比较。

这条规则避免在 Claude 或 Codex 正在运行时同步，因半行内容产生不存在的“分叉”。如果文件完整换行结束，备份可直接流式复制并计算 SHA-256；只有存在半行时才截取到上一个换行。

## 7. 跨机项目定位与恢复

项目身份强度为：

```text
remote: 规范化 Git 远端，跨机稳定
local:  本机规范路径哈希，只在当前电脑稳定
unknown: 无法识别
```

备份已有的强身份不会被另一台电脑更弱的识别结果覆盖。恢复 Claude 会话时：

1. 优先用 `remote:` projectId 在当前仓库清单中寻找本机项目目录。
2. 找到后按本机真实路径重建 Claude 的编码目录。
3. 找不到时尝试备份记录的项目路径或 provider 相对路径，但必须保持在 provider 根目录内。

Codex 会话优先按原始相对路径恢复；缺少相对路径时落到 `sessions/restored/`。会话原文中的旧电脑 `cwd` 不会被改写。

恢复文件会把 mtime 设为备份更新时间，使后续同步能使用大小 + mtime 快速通道。没有远端的本地项目无法跨机推导新路径，Fleet 不会猜测连字符编码对应的目录。

## 8. 删除与继续命令

普通删除只处理当前电脑的会话文件，并移到系统废纸篓，可尝试从废纸篓恢复。勾选“同时移出备份”时，Fleet 才会在受管备份仓写删除墓碑；另一台电脑已有文件时不会被静默删除，而是在同步时要求决定。

继续命令示例：

```sh
cd '<项目目录>' && claude --resume '<sessionId>'
cd '<项目目录>' && codex resume '<sessionId>'
```

界面可附加共享合同中定义的权限跳过参数：

- Claude：`--dangerously-skip-permissions`
- Codex：`--dangerously-bypass-approvals-and-sandbox`

该选项默认关闭，仅保存在当前浏览器的本机存储中。项目目录和会话 ID 都经过 shell 引用，命令只用于复制；Moo Fleet 不执行命令。

## 9. 安全与隐私边界

- 只同步 Claude / Codex 的完整会话 JSONL，不同步项目源码、未提交改动、登录态、API Key、Cookie、缓存、SQLite/WAL/SHM、锁文件或机器配置。
- 备份仓由 Fleet 独占管理。不要手工放入其他文件，也不要把用户代码仓当备份位置。
- 会话同步、冲突处理和删除串行执行，避免 `index.lock`、并发 reset 和相互覆盖。
- 远端同步使用普通 Fetch 和非 force Push；内容合并发生在会话层，不执行会掩盖分叉的 Git merge。
- 会话内容在备份仓和 Git 历史中是明文，任何拥有仓库读取权限的人都能看到。必须使用私有仓库并控制账号、部署密钥和镜像权限。
- 自动化必须显式设置临时 `GIT_FLEET_HOME`、`GIT_FLEET_CLAUDE_HOME` 和 `GIT_FLEET_CODEX_HOME`，不得使用真实会话目录作为夹具。
