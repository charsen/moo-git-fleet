# AI 会话双机同步

状态：v0.5 实现说明（2026-07-30）<br>
适用场景：上班一台电脑、下班一台电脑，用 Claude / Codex 辅助开发的个人开发者

> v0.3 的 Vault / checkpoint / handoff / WIP / epoch / lineage 设计已整体下线，历史稿保留在 Git 记录里（`git log -- docs/AI-SESSION-SYNC.md`）。本文描述的就是当前代码。

## 一句话

本机的 Claude / Codex 会话文件是真相，备份仓是它在你自己的私有 Git 里的一份副本；点一次「同步会话」，两台电脑对齐。

## 设置一次：选一个本机文件夹

备份仓就是一个普通的 Git 仓库，所以设置里**不需要填任何地址**——像添加代码仓库一样，从列表里选中它就行。
弹窗给出三种选择：

| 选项 | 什么时候用 | 提交给后端 |
| --- | --- | --- |
| 只备份在本机 | 只想在这台电脑上留一份副本 | `{ backupPath: null }`（落到 Fleet 数据目录下的 `session-backup`） |
| 列出来的候选文件夹 | 已经 clone 好的空私仓，或另一台电脑用过的会话备份仓 | `{ backupPath: '<候选绝对路径>' }` |
| 其他文件夹… | 候选没扫到（不在扫描根目录里） | `{ backupPath: '<手填绝对路径>' }` |

候选来自 `listBackupCandidates()`：遍历已配置的扫描根目录，只挑两类仓库——带 `fleet.json` 标记的会话备份仓（`kind: 'session-backup'`）、
以及还没有任何提交的空仓库（`kind: 'empty-repo'`）。其余仓库一律不列，因为同步会把工作树整体对齐远端。

### 两台电脑的完整故事

1. 在 Gitee / GitHub 上新建一个**空的私有仓库**（不要勾选 README、License 之类的初始化文件）。
2. **A 机**：`git clone <私有仓库> ~/ai-sessions`；打开 Fleet 的「AI 会话」页 → 点「同步会话」 → 在弹窗里选中 `ai-sessions` → 开始备份。
   Fleet 从这个仓库自己的 `origin` 读出远端，把本机全部会话写进去并 push。
3. **B 机**：`git clone <同一个私有仓库> ~/ai-sessions`（这次 clone 下来是有内容的，里面已经有 `fleet.json`）；
   同样打开设置弹窗选中它——它会带着「会话备份仓」徽标出现在候选列表里。点一次「同步会话」，A 机的全部会话就落到 B 机上。
4. 之后每台电脑上下班各点一次「同步会话」即可。

选中的文件夹如果没有 `origin`，就是「只备份在本机」——完全合法，只是不跨电脑。
远端地址里带用户名 / 密码 / Token 的仓库会被拒绝：请用不带账号密码的地址重新 clone，或改用 SSH。

备份分支**跟着仓库自己的分支走**：clone 空私仓时 git 已按远端 HEAD 把本地分支设好（Gitee 默认 `master`、GitHub 默认 `main`），
fetch / push 都用这个分支，远端不会多出一个没人要的分支。只有 Fleet 自己在空目录里新建仓库时才用 `main`。

设置完成后还能改：会话页顶部的「更换备份位置」按钮会重新打开这个弹窗（当前位置默认选中）。
换到新位置不会删除原位置的备份，下次同步会把全部会话重新写进新位置。

## 用户看到的五件事

1. **列表**：打开页面自动扫描本机全部 Claude / Codex 会话，可搜索、可预览真实对话。
2. **同步**：点「同步会话」——先收下另一台电脑的最新备份，再把本机的变化写进备份，最后统一 push 一次。
3. **决定**：只有真分叉、以及「另一台删了本机还在」两种情况会停下来问你，其余全自动。
4. **删除**：默认只把本机会话移进系统废纸篓；勾选后才会在备份里留一条删除记录。
5. **继续**：详情里给出「在终端里接着这个会话」的命令，一键复制。Fleet 自己不启动 provider。

### 继续会话的命令

```sh
cd '<项目目录>' && claude --resume '<sessionId>' [--dangerously-skip-permissions]
cd '<项目目录>' && codex  resume  '<sessionId>' [--dangerously-bypass-approvals-and-sandbox]
```

跳过权限确认是界面上的一个勾选项，选择记在本机（`localStorage`），默认不勾。参数本身由
`src/shared/provider-command.ts` 统一给出——它是产品要保留的选项，不要当成"没人用的代码"删掉。
项目目录和会话 ID 都经过 shell 引用，命令只用于展示和复制，Fleet 不执行它。

## 备份仓长什么样

```text
<备份仓>/
├── fleet.json                                  # 标记这是 Fleet 的会话备份仓
└── sessions/
    ├── claude/<providerSessionId>.jsonl        # 会话原文，原样保存
    ├── claude/<providerSessionId>.json         # 标题·项目·来源设备·行数·sha256·墓碑
    └── codex/...
```

一条会话一对文件。会话 JSONL 是追加写的，所以 Git 的 diff 天然是增量；删除会话就是删掉 `.jsonl`、把 `.json` 标成墓碑（`deleted: true`）。没有事件流、没有对象目录、没有纪元。

## 只处理写完整的行

provider 可能正在往会话文件里写最后一行。写完整的一行必然以换行结尾，因此没有换行结尾的尾巴一律不进备份、也不参与比对——
否则那行写完之后，两边就会被判成"分叉"，逼你去选一个根本不存在的冲突。这也意味着 Claude 正在跑的时候点同步是安全的。

## 比对规则：只比前缀

会话文件只在末尾追加、不改写已有行，因此「谁更全」逐行比前缀就够了（`src/server/sessions/compare.ts`）：

| 情况 | 结果 | 处理 |
| --- | --- | --- |
| 两边内容一致 | `same` | 跳过 |
| 只有本机有 | `local-only` | 写进备份 |
| 只有备份有 | `backup-only` | 恢复到本机 |
| 本机包含备份全部内容 | `local-ahead` | 用本机更新备份 |
| 备份包含本机全部内容 | `backup-ahead` | 追加到本机 |
| 从某一行起各写各的 | `diverged` | 问用户：用本机 / 用备份 / 两份都留 |
| 备份是墓碑、本机还在 | `backup-deleted` | 问用户：保留本机 / 本机也删 |

自动处理的四种都不会丢内容——更全的一方包含另一方的全部内容。会问用户的两种，任何一个选项都不会静默覆盖。

## 同步流程

`runSessionSync()`（`src/server/sessions/sync-run.ts`）：

1. `git fetch` 后把备份仓工作树 `reset --hard` 到远端最新。备份仓内容都能从本机会话重新生成，所以直接跟随远端最省事，也不会产生合并冲突。
   唯一生成不回来的是**墓碑**（本机已删掉的会话），因此对齐前先记下本机墓碑，对齐后把仍比远端新的补回去——否则离线时做的删除会在下次同步被悄悄撤销。
2. 扫描本机会话 + 读备份清单，按 `provider:sessionId` 配对。
3. 逐条比对，按上表自动处理，剩下的进 `pending` 返回给界面。
4. `commit` 一次、`push` 一次。

连不上私有 Git 不算同步失败：本机备份照常完成，界面上说明「这次只在本机备份」，落下的提交在下次联网同步时一起带上去。

推送永远是快进：工作树先对齐远端，再把本机内容写上去，所以不需要在 Git 层做内容合并。

## 恢复到另一台电脑的落点

Claude 的会话目录名编码了项目绝对路径，两台电脑不一样，因此恢复时：

1. 先按 `projectId`（由 Git 远端规范化推导）在本机 Fleet 仓库列表里找同一个项目，找到就按本机路径重建目录——**同一个远端在两台电脑上必然得到同一个 projectId，不需要任何映射表**。
2. 找不到就按备份里记录的相对路径原样落地，至少能在列表里看到、能预览。
3. Codex 的会话路径不含项目信息，直接按相对路径落地。

## 接口（8 条）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/session-backup` | 备份位置、远端、上次同步 |

## 边界

- 不同步项目源码、未提交改动、登录态、API Key、Cookie、缓存、SQLite/WAL/SHM、锁文件、机器配置。
- 不复制整个 `~/.claude`、`~/.codex`，只处理会话 JSONL。
- 备份仓必须在 Fleet 源码仓库之外，且不能嵌套在别的 Git 仓库里；远端地址不能内嵌凭据。
- Fleet 不再保存任何用户填写的 Git 地址：远端只从所选文件夹自身的 `origin` 读出，改远端就在那个仓库里 `git remote set-url`。
- 内容在私有仓库里是明文：任何能访问那个仓库的人都能读到会话内容，Git 历史也会长期保留。
- 不做实时同步；同步只在你点击时发生。
- 会话原文原样保存，不改内容。因此 Codex 会话里记录的 `cwd` 仍是它当初运行的那台电脑的路径——
  在另一台电脑上可以查看和搜索，直接 resume 时工作目录可能对不上。
- 备份仓的写操作（同步、处理冲突、删除）在进程内串行执行，同时点多次只会排队，不会撞上 git 的 index.lock。
