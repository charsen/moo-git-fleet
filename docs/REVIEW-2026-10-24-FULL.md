## 二、发现并修复的问题

### 1. 全量测试在默认并发下会假失败（工程缺陷）

14 核机器上 vitest 默认开 13 个 worker，而这套用例绝大多数在起真实 git 进程
（`scanner` / `stash` / `conflicts` 一个用例能起十几个）。首轮 `vitest run` 报了
**12 个文件失败 / 9~12 项失败**，原因全是 `Test timed out`、`Worker exited unexpectedly`、
`broker.sock ECONNREFUSED` —— 资源被抢空，不是被测代码有问题：同一批文件串行重跑 62 项全过。

`vite.config.ts` 的 `test.maxWorkers` 定为 4。限并发后 119 文件全绿，而且**更快**
（131s → 103s）：争抢本身比串行更贵。

### 2. 顶栏「AI会话」少了中英之间的空格（文案不一致）

`App.vue:5276` 写的是 `AI会话`，而页面标题（`SessionRelay.vue` 的 `AI 会话`）、
`styles.css` 的两处注释、verify 脚本用的都是带空格的写法。除了读起来不一致，
它还把 UI 验收的整组会话断言带崩了：`clickText('AI 会话')` 找不到入口，
「切到 AI 会话页」失败后，概览、胶囊、详情抽屉等 9 项全部连带失败。

统一为 `AI 会话`。修完这 10 项一次转绿。

### 3. UI 验收脚本在浏览器崩溃时沉默挂起（真缺陷）

首轮 `npm run verify:ui` 直接 `EXIT=13`，日志只留一句
`unsettled top-level await at verify.mjs:242 await send('Page.enable')`。

逐层排查后确认根因：**Chrome 在这个沙箱里初始化不了自己的进程沙箱**
（`sandbox initialization failed: Operation not permitted`），GPU 进程连崩六次后
`FATAL: GPU process isn't usable. Goodbye.`，浏览器整体退出 —— WebSocket 刚握手
（101）就被断开。脚本却没有任何 `onclose` 处理，`send()` 的 Promise 永远不 settle，
Node 发现事件循环空了就报一句「未结算的顶层 await」。

两处修复：

- `verify.mjs` 增加 `ws.onclose`：把所有在飞命令立刻 reject，并给出可读原因
  （区分「Chrome 已退出」与「连接被关」，附带受限环境该设的环境变量）；
- 顺带记录 `chrome.on('exit')`，崩溃时能报出退出码与信号。

根因是环境限制而非脚本缺陷，所以没有把 `--no-sandbox --disable-gpu` 设成默认值——
只在受限环境显式传。修完之后脚本对「浏览器崩了」这件事从沉默变成一句话说清。

### 4. 热力图只有鼠标能用（a11y，TODOS 里登记但一直没做）

735 个格子（近两年）全是 SVG `rect` + `@mouseenter`，没有 `tabindex`、没有键盘事件、
没有逐格 `aria-label`。键盘用户和读屏用户看不到任何一天的提交数。

按 TODOS 里已定的方向实现，但**没有**给 735 个格子逐个加 `tabindex`：

- 整张 SVG 是唯一 Tab 站点（`role="group"` + `tabindex="0"`），`aria-label` 写明可用方向键；
- `ArrowLeft` / `ArrowRight` 换一列（周），`ArrowUp` / `ArrowDown` 换一行（星期），
  到边界停住**且 `preventDefault`**，否则方向键会顺带把页面滚走；
- `Home` / `End` 跳首尾周，落点是未来日期时退到该列最后一个已发生的那天；
- 聚焦格用 2px `--color-focus` 描边（不降透明度，和 hover 的 1px 灰区分开）；
- `.sr-only` + `aria-live="polite"` 播报「2026-10-24 周六 · 4 次提交」。

移动规则抽成 `heatmap-grid.ts` 的 `moveHeatmapCursor` / `initialHeatmapCursor` 纯函数，
补 8 项单测；verify 里补 11 项真机断言（含「首列再按左不动且页面不滚」）。

### 5. 两条 git 竞态用例用固定 `sleep` 开窗，满负载下会假通过

`files.test.ts` 里「提交前的暂存区被改」和「预览中的暂存区被改」两条用例，都在假 `git`
包装脚本里 `sleep 0.25` 来制造一个窗口，测试则在这个窗口里 `git add` 一个新文件。
窗口是按时长定的，机器一忙（四个 worker 同时在起 git 子进程）就可能出现

- 测试自己的 `git add` 还没落地，0.25 秒已经过完 → 提交顺利完成 → 用例在
  `rejectionOf()` 上报「Expected promise to reject」，看起来像被测代码有 bug；
- 反过来的极端情况：`git add` 抢在指纹快照之前完成，一样变成假通过。

这类假通过比假失败更危险——它让「并发护栏还在」这件事失去证据。改成**握手**：

- 包装脚本不再睡固定时长，而是轮询一个「放手文件」，上限 8 秒（`i -lt 400` × `sleep 0.02`）；
- 测试在 `git add` 落地之后才写这个文件，两边由事件而非时长对齐。

变异验证（确认用例仍然有咬合力）：把 `files.ts:288` 的预览护栏、`:302` 的提交前
`snapshotFingerprint` 比对分别改成恒假，对应用例各自失败；还原后 3 次单跑 15/15 通过。

## 六、时间段支持自由选择日期

### 问题

时间段只有四个预设（13 / 26 / 52 / 104 周）。查一个迭代的起止、某次上线前后两周、
某个月的月报，这四个都不对——只能挑一个最接近的，然后在心里折算。

### 方案：预设 + 自定义，自定义精确到天

工具栏的按钮组里多了一个「自定义」。点它展开一行两个原生 `date` 输入（预填当前正在看的
起止日期）+ 天数回显 + 应用/取消。「应用」在起止颠倒、日期不存在、超过 5 年时是禁用的，
并直接说明哪里不对——服务端对这些输入一律回落默认窗口（只读接口不报错的既有策略），
但回落是兜底，不该让用户以为自己的选择生效了。

两个关键决定：

1. **自定义范围精确到天，不对齐整周。** 预设窗口天然是整周（周一 → 周日），所以以前
   「周数」这一种表达就够了；一旦能选 10-01 ~ 10-15，再多算三天就不是用户要的口径。
   服务端按 `[start, end]` 闭区间裁 `daily` / `hourly` / 作者 / 非上班时间 / 代码量。
2. **热力图仍然按整周画列，行必须对应星期。** 所以网格向外扩到 start 所在周的周一、
   end 所在周的周日；多出来的格子 `inWindow: false`，不绘制、不计数、键盘也走不过去。
   图好看和数字准确是两件事，不能让前者改后者。

## 七、数据来源：分析读的是本地副本（补提示文案）

### 结论

分析页**完全不联网**。后端只跑三条本地只读 git 命令：`git log --branches --remotes --tags HEAD`
（`analytics/heatmap.ts:33`）、`rev-list`（`:391`）、`rev-parse`（`:266`）。其中 `--remotes` 读的是
`refs/remotes/*`，也就是**上一次 fetch 留在本地的快照**，不是远端实时状态。

fetch 是完全独立的另一条链路：手动按钮（`git/actions.ts:141`）、批量任务（`app.ts:741`）、
客户端自动定时器（`App.vue:2174`，`autoFetchIntervalMinutes` 默认 `0` 即关闭）。analytics 从不触发它们。

缓存分两层，都在本机：git 对象库 + 进程内 `scanCache`（`heatmap.ts:307`，key 为仓库绝对路径，
LRU 上限 256 条 / 50 万条提交时间 / 6 万天，进程重启即失效）。失效判据是全部分支 + 远程 + tag +
HEAD 的 sha 哈希 `refSignature`（`:264`）；每次请求仍会跑一次本地 `rev-parse`，哈希没变就复用整份
全历史 log，变了才重扫。时间窗口**不进缓存键**，切时间段只是 `windowLog`（`:161`）在内存里挑日期求和。

### 问题

「刷新」按钮走 `invalidateQueries`（`App.vue:2219`），服务端命中缓存后原样返回——**不会去远端拿新提交**。
加上自动 fetch 默认关闭，一台从没 fetch 过的机器可以永远看着一份旧数据，而界面上一句解释都没有。
「同事昨天推的提交怎么没有」会直接变成一个 bug 报告。

### 方案：常显一句来源说明，不写截止时间

工具栏下方一行 12px 灰字，带一个 12px 的 `RefreshCw`：

> 分析读的是本地仓库副本，不连接远端；远端有新提交要先 Fetch 才会更新，记得及时 Fetch。

刻意**不做**的事：

- 不显示「截至某次 fetch 的时间」。要准确就得把 `latestFetchBatchAt` 拉进分析页并跟着 60 秒轮询同步，
  多一次请求、多一个会过期的状态；而用户真正需要知道的是「为什么看不到最新提交、该做什么」。
- 不做成可关闭的提示条。关掉之后就没人再提醒「这里是本地副本」，而这是理解整页数字的前提。
- 不塞进工具栏。工具栏是三个口径的开关区，验收里有一条「工具栏单行」的断言；说明文字进
  去会把 1024 px 下的单行布局挤成两行。

### 验证

- 类型检查 `vue-tsc` / `tsc`、`eslint .`：0 问题。
- 单测 120 文件全通过。
- 真机 UI 验收 **284 项全通过**（280 → +4）：写明基于本地数据、不写具体截止时间、
  单独成行不在工具栏里、可见且不换行。
- 截图核对 1440 / 1024：两种情况都是单行、左边缘与工具栏对齐、没有挤压下面的热力图卡片。

## 八、换时间段后的体量：热力图不再随周期变形

### 问题（真机量出来的）

同一个卡片在四个预设之间切换，量到的是：

| 预设 | 列数 | 格子 | 卡片高度 |
|---|---|---|---|
| 近 3 个月 | 14 | 25.9px | **265px** |
| 近 6 个月 | 26 | 25.9px | 265px |
| 近一年 | 52 | 19.4px | 198px |
| 近两年 | 104 | 10px | **102px** |

三件事叠在一起：

1. **高度在三档之间来回跳**（265 → 198 → 102）。点一下按钮，整页往下挪一百多像素，
   下面的统计卡、非上班时间卡跟着上下位移——这是「换周期后不好看」最刺眼的来源，
   比留白更难受。
2. **短窗口格子被放大到 26px**，14 列铺成一面大色块；近两年又被压到 10px。同一张图
   在两种尺度之间反复切换，读者对「一格多大」没有稳定预期。
3. **图例贴在卡片的右边缘**，不是图的右边缘。近 3 个月时图只有 362px 宽，图例在
   1000px 之外，两个元素各说各话。

### 方案

- **格子上限按列数分档**：列数 ≥ 40（近一年以上）时仍放宽到 26px，让 1920 以上的
  宽屏铺得满；短窗口钉在 18px。卡片高度随之稳定在 **304 / 304 / 317 / 221**，
  短窗口到近一年的落差从 67px 收到 13px。
- **宽度上下界改成按格子边长换算**（`chartWidth * maxRenderedCell / cellSize`），
  去掉原来 2.16 这个魔法倍数——语义从「乘一个数」变成「一格最多 18/26px、最少 9px」。
- **图与图例包进 `.heatmap-plot`**，盒子宽度由格子尺寸决定，图例右对齐到图的右端。
  短窗口时两者是一个视觉单元，不再是卡片两端的两块东西。
- 盒子**靠左不居中**：整卡的标题、副标题、下方统计卡全部左对齐，图挪到中间会
  「浮」在卡片里，和标题的左边缘对不上。

### 刻意不做

- **放大格子去填满**：近 3 个月只有 14 列，要铺满 1332px 得一格 80px，那是一面色块
  墙，不是热力图。留白是信息量决定的。
- **短窗口改成按天为列**：45 天按天画是 45 列，但每天只落在星期几那一行，其余六行
  恒空，图形会碎成一把对角线；按一行为列又变成另一种图（提交条带），键盘移动、
  月份刻度、tooltip 全要重写。这属于换图表，不属于调样式。
- **居中**：见上，会把图从卡片的左对齐基线里拽出来。

### 验证

- 真机 UI 验收 **290 项全通过**（284 → +6）：四个预设的高度 304/304/317/221、
  短窗口格子 ≤ 19px、近一年铺满 1332px、近两年格子仍是 10px（色阶分得清）、
  图例与图右端的偏移 **0/0/0/0px**。
- 截图核对 1440 / 1024 / 1920：近一年在 1440 与 1024 都铺满，1920 上按 26px 放大
  继续铺满；近 3 个月在 1440 稳在 304px 高，不再长到 265px。
