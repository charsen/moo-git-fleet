# Git 基础功能体验复盘（2026-10-20）

对「已经能用、但用起来别扭」的 Git 基础功能做一次视觉与操作复查。范围只限基础功能，不含新功能提案；`TODOS.md` 里「明确不做」的条目没有重复提。

## 方法与环境

- 隔离实例：`GIT_FLEET_HOME` / `GIT_FLEET_CLAUDE_HOME` / `GIT_FLEET_CODEX_HOME` 全部指向 `/tmp/mf-ux/`，后端 8787、前端 5173，全程未接触真实仓库、真实会话与真实凭据。
- 12 个夹具仓库，刻意造出基础功能最容易翻车的状态：脏工作区（暂存 + 未暂存 + 改名 + 删除 + 二进制 + 深层路径 + 中文与 emoji 文件名）、**合并冲突进行中**、**detached HEAD**、**空仓库（unborn 分支）**、**有远端但分支无 upstream**、**完全没有远端**、60 个提交、超长分支名、多分支多标签、1 个 stash。
- 交互用 CDP 真实鼠标与键盘驱动（`Input.dispatchMouseEvent` / `dispatchKeyEvent`），不是 `element.click()`；视口 1440×900 与 1024×800 两档。
- 除「暂存一个文件」「取当前侧」两个用于验证反馈的动作外未执行写操作；夹具仓库的 `git status` 与界面显示逐条核对过。

## P1

### 1. 键盘 Enter 打开仓库会连带弹开项目切换菜单

在仓库列表里聚焦一行按 Enter：仓库打开的同时，左上角项目切换下拉自己展开了。

实测对照（同一夹具、同一动作，只改事件参数）：

| 触发方式 | 仓库打开 | 项目切换下拉 |
| --- | --- | --- |
| 鼠标点击行 | 是 | 否 |
| Enter（`keyDown` 带 text，等同真实按键） | 是 | **是** |
| Enter（`rawKeyDown`，不带 text） | 是 | 否 |

机制：`App.vue:5146` 的 `@keydown.enter.self="selectRepository"` 没有 `preventDefault()`，打开仓库时焦点已经移到项目切换按钮上；真实按键会在 keydown 之后补一个 keypress，它落到新的焦点元素（`<button>`）上，触发原生 click，于是 `SelectMenu` 的 `@click="toggle"` 被点开。`rawKeyDown` 不产生 keypress，所以不触发——这也解释了为什么鼠标用户完全看不到这个问题。

影响：只用键盘的用户每次进仓库都要先 Esc 关掉一个没人要的菜单；更糟的是「多按一次 Enter」会把菜单里的第一项选中，直接跳到别的仓库。

建议：`selectRepository` 里 `event.preventDefault()`（取消后续 keypress），或把焦点移动推迟到 `keyup` 之后；同时给这条路径补一个键盘用例。

### 2. 新分支在工作台内无法建立 upstream / 首次发布

给 `analytics-etl` 造了一个有远端、但新分支 `topic/no-upstream` 没有 upstream 的状态。工作台顶栏：

```
Fetch        | enabled  | title=（空）
Pull 0       | DISABLED | title=当前分支没有 upstream
Push 0       | DISABLED | title=当前分支没有 upstream
同步         | DISABLED | title=当前分支没有 upstream
```

三个按钮全灰，唯一的解释挂在 `title` 上。而本仓 `NOTES.md` 已经记录过「`disabled` 按钮上的 `title` 不可依赖：禁用表单控件不派发鼠标事件，两种内核都弹不出 tooltip」——这里正是那个已知失效模式。左下的分支卡片只显示「未关联 upstream / — 待推送 — 待拉取」和「对比」「删除」，也没有发布入口。

唯一能用的路径在**另一个界面**：回到仓库列表，点该行状态列的「未关联」胶囊，才会弹出设计得相当完整的 UPSTREAM REPAIR 弹窗（本地分支 / 确认 HEAD / 写入范围 / 首次推送目标 / 二次确认）。

影响：用户在仓库里改完代码想推一个新分支，看到三个灰按钮，无从下手；要自己想到「退出去点那个小胶囊」。

建议：至少在工作台内给一条可见出口（例如三个按钮旁的 `branch-panel-blocker` 式内联说明 + 「发布此分支…」），复用已有的 upstream repair 流程，不新增能力。

### 3. detached HEAD 只有一行小字

`detached-lab` 的 `git status` 是 detached HEAD。工作区里能搜到 `DETACHED` 字样，但它的位置是标题下方那一行次要文本：

```
工作区
DETACHED · 0 个文件
```

同一份界面里，「进行中的操作（MERGE）」有黄色边框 banner + 两个按钮，「冲突」有红色计数和四个处理按钮；detached HEAD 这个同样会让人丢提交的状态，没有任何 banner、没有解释、没有「新建分支并切到这里」的出口。提交按钮在干净的 detached 工作区里和其它状态长得完全一样，用户在这里提交会得到一条不在任何分支上的提交。

影响：基础 Git 里最容易造成「我的提交去哪了」的状态，被降级成了和「3 个文件」同级的灰字。

建议：沿用现有 banner 组件，给一行「当前不在任何分支上（detached HEAD）。在此提交不会属于任何分支」，并提供「新建分支并切换到此提交」；提交前若处于 detached，加一次明确确认。

## P2

### 4. 工作区徽标 `S/M/U/C` 没有可解释性

仓库列表「工作区」列的徽标：

```
<span class="count staged">S 1</span>
<span class="count modified">M 2</span>
<span class="count untracked">U 2</span>
<span class="count conflict">C 1</span>
```

四个元素都没有 `title`，也没有 `aria-label`。同一张表里，「状态」列的胶囊是做得对的：`aria-label="many-commits 未设置 upstream，打开一键修复"` + `title` + `aria-haspopup`。两相对照，徽标这一组是明显的遗漏。

影响：新用户必须猜 `S/M/U/C` 的含义（`C` 尤其不直观，其实是冲突）；屏幕阅读器读出来是「S 一」「M 二」。这个位置恰恰是用户判断「哪个仓库要处理」的第一眼信息。

建议：补 `aria-label`（如「1 个已暂存文件」）与 `title`；`C` 可以考虑直接用「冲突」文字或图标，与右侧状态列语义对齐。

### 5. 分支管理面板里超长分支名压住 CURRENT 徽标

`long-names` 仓库的分支名是 78 字符。分支面板里它和 `CURRENT` 徽标叠在一起：

- 面板：`left=241`，`width=460` → 右边界 701
- 分支名元素：`left=303`，`right=973` → 比面板右边界多出 272 px
- 徽标与文本矩形判定 `overlap=true`

截图里能直接看到 `feature/very-long-branch-na` 被 `CURRENT` 压住、后面的字符才继续露出。左侧栏的同名分支是正常省略号截断且有 `title`，所以问题只在面板这一处。

建议：分支名容器加 `min-width:0` + `text-overflow:ellipsis`，徽标 `flex:none`，不要用绝对定位覆盖。

### 6. 批量 Fetch 把「仓库没有远端」计为失败

三个刻意没有远端的夹具（`local-only` / `many-commits` / `fresh-empty`）在批量 Fetch 后，操作记录里都是红点失败，文案统一为「仓库缺少 remote：origin」，面板右上角因此常驻「需处理 3」。

这些仓库不是坏了，它们本来就没有远端。把它们算成失败，等于让「需处理」这个计数永远归不了零，用户会逐渐忽略它——那这个指标就失去意义了。

建议：批量动作前按能力筛选，没有远端的仓库直接跳过（或在结果里给中性态「未配置远端」，不参与「需处理」计数）；单仓 Fetch 仍可保留失败语义。

### 7. 二进制文件的 diff 把原始 patch 当正文

`long-names` 里的 `assets.bin` 选中后，右栏标题显示 `BIN +0 −0`，正文却是：

```
diff --git a/assets.bin b/assets.bin
new file mode 100644
index 0000000..0f49c4a
Binary files /dev/null and b/assets.bin differ
```

这四行是 git 的补丁头，不是文件内容。界面上既没有「二进制文件无法预览」的空态，也没有体积、类型、是否为新文件这些真正有用的信息。（对照：提交历史里选中二进制文件时同样是这条路。）

建议：`diff-presentation` 识别到二进制标记时直接给结构化空态，复用历史文件树里已有的「二进制或非 UTF-8 文件 / 没有文本预览」写法。

### 8. 合并入口藏得深

合并能力是有的，但入口是两条都不显眼的路：

1. 鼠标把侧栏分支行拖到当前分支行（`startBranchDrag` 只绑 `pointerdown`，**没有键盘等价操作**，Esc 只能取消）。
2. 先在侧栏点分支行「浏览」，左下角那张小卡片才会出现「合并到当前分支」。

分支管理面板里没有合并项，分支行右键也没有（右键在该面板上不弹菜单），「分支对比」页只有对比没有合并。

影响：`git merge` 是最高频的分支操作之一，现在既不可键盘完成，也没有任何提示告诉用户「可以拖」。不看文档的用户大概率找不到。

建议：在分支行的操作区（已有「重命名」「删除」两个图标按钮）加一个「合并到当前分支」，复用现有 `BranchMergeDialog` 与预检；拖拽作为快捷方式保留。

## P3

### 9. 设置「远端」的空态文案与实际列表矛盾

`设置 → 远端` 顶部写着：

> 还没有可管理的远端主机。先在「仓库接入」里添加仓库。

而同一屏下方「逐仓库远端」列着 6 个带远端的仓库（`conflict-lab` / `long-names` / `northwind-api` / …），甚至有一行标出 `fresh-empty` 缺少 origin。

代码里这条文案的判据是 `credentialOverview.hosts.length === 0`（`App.vue:5816`），也就是**凭证主机**为空，不是「没有远端」。夹具的远端都是本地路径，所以主机数为 0 就触发了这句。文案与判据对不上，给出的补救动作（去加仓库）也不会解决问题。

建议：改成「还没有录入任何远端凭证」，并在有仓库但无凭证时给出「在下方逐仓库远端里补地址，或在此录入凭证」。

### 10. 从未推送的标签仍可「删除远端」

`analytics-etl` 的 `v0.2.0` 只存在于本地。详情栏三个按钮实测：

```
推送      | enabled | title=推送到远端
删除远端  | ENABLED | title=删除远端标签
删除      | enabled | title=删除本地标签
```

「推送」是灰的才对、结果它可点（对），但「删除远端」也可点——这个标签远端根本没有，点下去只能失败。列表里也没有「是否已推送」的标记，用户无从判断。

建议：按标签的远端存在性决定「删除远端」可用性，并在行内补一个「仅本地 / 已推送」标记（远端分支已经有类似的视觉语言可以复用）。

### 11. 提交列表用完整标题换行

`long-names` 里一条 60 字的提交说明在历史列表里占了三行，`many-commits` 的中等长度说明占两行。列表因此行高不齐，扫读节奏被打断；右侧详情又把同样的标题整段放大再显示一遍。

建议：列表按单行截断 + `title`，完整内容留在详情（现在详情已经有了）。

### 12. 1024 px 下工作区徽标竖排

1440 px 时 `S 1 M 2 U 2` 横排；1024 px 时变成三行竖排，同一行的仓库行高从 40 px 左右涨到 90 px 以上，与相邻行完全不对齐。

建议：窄视口下改成「一个徽标 + 总数」或收成图标 + 数字的单行紧凑形态。

## 做得好的部分（这次一并确认过，别在改动中弄坏）

- **冲突处理**：进行中操作 banner（含「全部解决后才能继续」与禁用原因）→ 文件行四个动作 → 右侧三侧预览 → 「取当前侧」确认弹窗写明「只影响这一个文件，不会自动提交」并解释了 `ours` / `theirs` 在 rebase 下的语义差异。这是全应用最完整的一条链路。
- **UPSTREAM REPAIR 弹窗**：本地分支 / 确认 HEAD / 写入范围三栏 + 首次推送目标 + 二次确认，信息密度和克制都合适。
- **Pull 确认弹窗**：范围、rebase 选项、冲突会暂停，三条说明都在，按钮用琥珀色而不是危险红。
- **hunk 暂存**：按钮 `aria-label="暂存此块：@@ -1,3 +1,4 @@"`，把 hunk 头带进无障碍名称，这个细节很到位。
- **文件行操作**：`aria-label="丢弃本地修改 src/handler.ts"`、`"移到废纸篓 NOTES.md"`，动作和对象都在名字里。
- **diff 语法高亮确实生效**：实测 token 分布 `keyword 7 / plain 17 / function 3 / constant 2 / string 1`，`export` 为 `rgb(167,139,250)`、`handle` 为 `rgb(124,197,255)`；`meta` 行有独立的斜体灰样式。截图缩小后容易误判成「没有高亮」，实际是有的。
- **长分支名截断**：左侧栏与工作区标题都有 `title`，省略号正常。

### 改动中值得记住的两点

- **常驻提示不能放进只在某个视图渲染的插槽。** 干净工作区默认打开「提交历史」（`RepositoryWorkspace` 的 `initialViewResolved` 逻辑），最初把 detached banner 放进 `#operation`，结果在最常见的情况下根本不渲染。改为组件级 `#notice` 插槽，跨视图可见。
- **`align-items: flex-start` + `white-space: nowrap` 会让省略号失效。** 列方向 flex 容器里的子项按 max-content 收缩，`overflow: hidden` 拿不到可裁的宽度；必须补 `max-width: 100%` 把它夹回列宽。

## 第二轮：把「只看了入口」的写操作全部实跑一遍（2026-10-21）

上一轮明确留了一句「合并、rebase、继续/中止这些写操作只看了入口与弹窗，没有实际执行」。

### 这一轮最值得记住的一条

**「暂停」不是「失败」。** 冲突暂停时 Git 的状态已经变了（HEAD 游离、index 多了未合并项），

## 第三轮：大差异的两件事（2026-10-21）

这一轮从「diff 滚动卡顿」查起，结论和起因正好相反：**卡顿不存在，真正的问题是截断在骗人。**

### 先说卡顿：是测量方法错了，不是渲染慢

第一轮量到「2000 行 diff 滚动 avg 18 ms / p95 30.9 ms / max 57.4 ms」，超出 16.7 ms 预算。
重测时把冷态和热态分开，并把每帧步长从 `scrollHeight / 40`（≈ 1900 px，一帧跳三屏）
改成 `clientHeight * 0.9`（不到一屏，接近真实滚动）：

| 测量 | 帧数 | avg | p95 | max | 超 20 ms 帧数 |
| --- | --- | --- | --- | --- | --- |
| 冷态（首次滚完） | 128 | 17.1 ms | 17.3 ms | 68.5 ms | 2 |
| 热态（再滚一遍） | 128 | 16.7 ms | 17.4 ms | 18.3 ms | 0 |

也就是说：**稳态满帧，只有首次光栅化掉了 2 帧。** 原来的数字是「每帧逼浏览器光栅化三个视口」量出来的。

顺带排除掉两个候选优化：

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| `content-visibility: auto` + `contain-intrinsic-size` | 冷态 p95 升到 20.1 ms，凭空多出 486–655 ms 布局耗时（基线为 0） | **更差，不采用** |
| 去掉行号栏的 `position: sticky` | 主线程任务从 1881 ms 降到 956 ms，帧时间**完全不变** | 开销被帧预算吸收，用户看不见，不值得牺牲横向冻结 |

而且 diff 渲染本身有硬上限：工作区差异 120 KB、提交差异 200 KB，所以「上万行把界面拖死」
这个悬崖在架构上就不存在——上限同时也是渲染护栏。

### 真正的问题：截断没有告诉任何人

`maxPatchBytes = 120_000` 会把超限补丁截断，但截断只做了两件事：往补丁尾部拼一句
`… diff 已截断 …`，以及在 `App.vue` 里靠 `dialog.diff.endsWith('… diff 已截断 …')`
把按块暂存关掉。于是：

| 现象 | 后果 |
| --- | --- |
| 拼接的提示语被当 diff 正文渲染 | 出现在 1657 行末尾的一行斜体灰字，等于看不见 |
| 页头 `+N −M` 由**截断后**的补丁算出 | 1 万行改动显示成 `+0 −1654`，读起来像「这个文件只删不加」 |
| 提交差异、Stash、文件预览都有「过大」提示 | 只有工作区这条没有，同一个 App 里两套口径 |

### 改法：截断从「文本」变成「字段」

- `fileDiff` 返回 `{ patch, truncated }`，不再往补丁里拼提示语。
- `/api/repositories/:id/diff` 多返回一个 `truncated`，`RepositoryDiff` 带着它流转。
- `App.vue` 的按块入口改用 `dialog.truncated`，不再嗅探字符串。
- 工作区差异头下方常驻一条提示：`文件差异过大，仅显示前 120 KB，增删行数已省略。完整差异请在本地 Git 中查看。`
- 截断时**不显示** `+N −M`：错数字比没数字更糟。未截断时照旧显示（`Markdown +2 −0`，按块按钮保留）。

### 复验

| 场景 | 结果 |
| --- | --- |
| 1 万行改动（截断） | 提示出现、`role="status"`、统计隐藏、按块按钮 0 个、补丁尾部不再有拼接文字 |
| 50 行改动（未截断） | 无提示、`Markdown +2 −0`、按块按钮 1 个 |
| 1024 / 1280 / 1440 布局 | 提示在 1024 换两行占 47 px（diff 区 544 px），1280/1440 单行 30 px；三者都无横向滚动、无页面溢出 |

### 这一轮最值得记住的一条

**测量方法本身会造假象。** 帧间隔只有在「一帧的滚动量接近真实操作」时才有意义；
用 `scrollHeight / 40` 当步长，量到的是光栅化吞吐，不是滚动流畅度。
在拿一个性能数字去改代码之前，先确认这个数字能被复现、且冷热态分开看。
