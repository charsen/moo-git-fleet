# 分支拖拽合并方案

2026-10-02。状态：按后续继续开发指令实现当前 HEAD 目标范围，完成真实 Git/API、浏览器和隔离原生窗口验证；用户另授权完成后本机安装及全面真机复查。

## Tower 对照

[官方合并说明](https://www.git-tower.com/help/guides/branches-and-tags/merge-rebase/mac)要求先检出接收改动的分支，再将源分支拖到当前 HEAD，或使用 Merge 入口。本机实操确认：拖到 HEAD 会打开 Merge 对话框并自动选中来源，拖到非当前分支本次未触发合并。对话框提供 Squash、始终生成合并提交、直接提交，以及签名验证和跳过 Hooks 等选项；本次仅查看与取消，没有执行真实仓库合并。

Fleet 在既有分支读取、切换、仓库写操作锁、操作记录与冲突处理链路上，新增只读预览和启动合并 API。

## 已实施范围

1. 本地与远端跟踪分支可作为拖拽来源；当前 HEAD 本地分支作为目标。目标行高亮，提示「将来源合并到目标」；相同分支、远端目标、其他仓库的拖拽不执行。拖到非当前本地分支提示先切换，不暗中切换。
2. 松手只打开一个合并确认框，明确展示来源、目标、双方提交 SHA 和将引入的提交数量。提供取消、合并，以及「始终生成合并提交」复选项；默认优先快进，分叉时创建普通合并提交。重复点击和执行中的项目切换均被保护。
3. 浏览来源分支时提供「合并到当前分支…」按钮作为拖拽之外的键盘可达路径，复用同一个确认与执行流程，保持现有顶部布局。
4. 已包含来源提交时显示无需合并，区别于失败。合并成功后刷新工作区、分支、历史和操作记录；保留源分支，不自动 Push 或删除分支。
5. 合并冲突视为已启动但暂停，跳转工作区并显示进行中的 merge；复用已有选取版本、标记解决、继续与中止操作。禁止普通提交绕过进行中操作的检查。

未实施的候选范围：允许任意本地分支作目标并先自动切换。当前只向已检出的 HEAD 合并。

## 数据与 Git 边界

- 沿用受信任根目录、session token、Origin/Host 检查及仓库操作锁。合并要求已有本地 HEAD 且没有进行中操作；本地改动只在**会与本次合并写入的路径重叠**时拦截，其余情况交给 Git，未跟踪文件与无关改动不再挡路。重叠时可在弹窗里勾选「先把这些改动存入 Stash 再合并」（需用户显式选择，不静默 Stash、不覆盖本地改动）。
- 预览为只读，来源限定现有 `refs/heads/*` 或 `refs/remotes/*`，使用结构化来源而不是自由输入 Git revision。执行前重取仓库状态、当前分支/HEAD、来源与目标完整 SHA，过期则拒绝；通过核实后的来源 SHA 执行，避免来源引用在执行中漂移。
- 显式选择普通 `--ff` 或 `--no-ff`；不继承会改变本次选择的 merge.ff 设置，不启用 autostash。保留用户已有 Hooks、身份与签名配置，避免弹出编辑器阻塞；失败信息与真实进行中状态必须同步展示。
- 合并要求已有 stage 与 commit 能力，不新增配置开关。Pull 仍只允许 fast-forward，Push 永不 force；此次普通 merge 不改变这些接口。
- 本轮不增加 rebase、squash、自动解决冲突、跳过 Hooks、拖拽即无确认执行、合并后自动 Push 或历史撤销。

## 实测与优化

- 定向 Git/API 验证快进、两父合并、no-FF、无需合并、本地/远端同名隔离、脏工作区、过期 HEAD/来源、冲突继续/中止与 Hook 阻止。冲突响应使用白名单 `merge-paused` 错误码返回工作区；操作记录保持既有失败状态并如实注明暂停原因。
- WKWebView 系统 HTML 拖拽在真机测试中停留于开始状态，改为 Pointer Events 内部拖放：移动阈值、HEAD 高亮、非 HEAD 提示、松手预览、Escape 取消、失焦清理与点击抑制。跨仓库或外部拖拽不进入此流程。原生实操完成本地快进、远端 no-FF、冲突选取版本并继续；Git 回读确认两个父提交、源分支和 Stash 保留。
- 收紧合并弹窗的边框、圆角、字号、留白与长名称显示；新增入口保持单行，避免拖拽产生文本选区。成功后显示当前分支最新提交。修正共享 SelectMenu 的关闭后 Escape 和焦点返回，补齐选项的无障碍名称。
- 浏览器复查工作区、历史、Stash、标签在 1024/1440 CSS px 与 14/16 px 字号下的 16 个组合，无根页面溢出、运行错误或失败网络响应。原生窗口另复查主列表、设置、项目菜单、键盘帮助、操作记录、仓库编辑与会话空态/备份设置入口；隔离文件完成勾选提交并保留未选文件。没有访问真实会话或执行任务外远端写入。

## 2026-10-03 脏工作区判定放宽与合并入口

- 预览不再用「工作区非空」一刀切拦截：改为用 `git diff --name-only <merge-base> <source>` 求出本次合并会写入的路径，与 `git status` 的本地改动取交集，只有重叠才拦，并列出前 20 条。未跟踪文件与无关改动交给 Git。`MergePreview` 新增 `dirty` / `conflicting` / `conflictingUntracked`；`blocker` 收窄为进行中操作、无共同历史与仓库配置禁止。
- 弹窗在存在重叠改动时提供「先把这些改动存入 Stash 再合并」（默认勾选、可取消；重叠含未跟踪文件时该子项必选）。执行时先 `stash push` 再合并，Stash 引用写回操作消息与返回结果。未勾选则拒绝合并。
- 详情顶部新增「合并」入口，选择本地或远端跟踪来源后复用同一个预览执行弹窗；解决默认进入当前分支历史时左下没有合并按钮的问题。
- 已知限制：合并冲突后工作区变脏，`applyStash` 的干净工作区前置会阻止立刻恢复该 Stash，需要先处理完冲突（或中止）再恢复。
